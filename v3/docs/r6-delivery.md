## 实验和判定边界

30 题包括 10 问答、10 跨源调查、5 纯函数修复、5 不足/越权。使用真实 DeepSeek、真实本地预训练检索和学习重排、独立 PostgreSQL 只读角色、固定 GitHub commit。数值/引用/Go 判定与模型执行器分离，不使用模型自评。

A/B/C 共用模型、价格、上下文、每任务最多三次调用及相同工具上限，按冻结随机顺序执行。比较范围是相同取证流程下的推理协作，不是自由工具规划能力。模型别名可固定，服务端不可见 revision 不可声称已固定；恢复造成的时间间隔也限制比较结论。

源码取证固定于 `62d41f9de3ef6dc50122c893756ee97f9e472c4e`。实际 GitHub 文件、完整 tree 及 SQL 行哈希已核验。30 项真实连接器/上下文预检通过，正常 QA/跨源的正例 Recall@5 为 20/20；这不等同模型答题正确率。题集是新 revision/dataVariant 的合成案例，开发者可见，不声称盲测未知领域。消融未运行。

实际失败暴露了需要改进的工程问题：无关知识干扰修复契约；布尔/空值等输出字段约定不够明确；数值与解释有矛盾；最终引用核验不能总在预算内纠正。仅布尔编码导致的四项失败另列分析，原严格分数不改。C 的一份实际合格补丁也因字段协议失败，说明不能将全部失败归因于模型不会修复。
