# ADR 0012：R6 监控、有限主动性和最终评测边界

状态：已实施；获授权的完整真实评测已执行，质量门槛 FAIL。继承 ADR 0001、0011。下列启动、中断和核账记录按发生顺序保留。

Watchdog 是独立最小环境进程，只使用环回 HTTP 和限权令牌。Engine 同一持锁连接负责心跳、健康记录、恢复建议及所有业务写入。Worker 每五秒更新 30 秒租约，心跳不生成进度事件。健康探测中的 Redis/MCP 网络访问在事务之外；PG 失联时不伪造已保存记录。恢复建议按项目、仓库、epoch 和事实版本去重。未知外部动作或未知计费只允许等待/转人工，即使 Run 已取消也继续可见；任何恢复建议都不自动重发。

主动策略默认 observe。显式完整 policy_hash 的 auto 激活绑定仓库、Issue、事件类型、actor、标签、固定 commit、可信问题和到期时间。签名 CI failure webhook 可触发，其他事件通过认证的类型化入口接入；这里没有通用依赖轮询器。事件正文只保存审计，不生成权限或替换问题。相同外部事件最多被一个策略认领；启动独立影子 Thread 的只读 Run，不挤占交互 Thread。每项策略独立限制总 Run/读取/模型调用/费用；live 策略还必须绑定已有付费许可，不能由策略创造新额度。撤销停止未完成任务但不退款未知预占。

只读 Run 的报告只存内部 CAS/账本。普通 Action 验证、修复提案入口再次检查 read_only；不创建外部 Action、Outbox 或可信记忆。观察和自动策略都不会批准发布。

最终集是新 revision/dataVariant 的 30 题：10 QA、10 跨源、5 种不同纯函数修复契约、5 不足/越权。开发者可见，因此不声称盲测未知领域。A 单分析者、B 固定两专家、C 按 required_roles 选择专家，三者共用确定性取证流程和相同模型/价格/上下文/3 次调用/16 个逻辑工具/180 秒上限。该比较隔离推理协作，不验证自由规划工具的能力。模型别名可冻结，服务端不可见 revision 不能假装已固定。

每臂 30 题共 90 分配项；物理调用最多 270，失败不重置。独立 Python 数值 Oracle、引用原文核验和隔离 Go 隐藏测试判定业务结果，执行器不导入 Oracle，隐藏期望不反馈给模型。不使用模型自评；语义解释是否充分仍需人工审阅。完整失败保留，固定分母和门槛，不因重试筛掉失败。未知费用保留预占并停止余下任务；改实现/输入要新 manifest，重跑和消融需另行授权。

累计仓库 US$2 硬限制由实际 usage_calls 聚合核验，跨 project 和 profile 生效；新增评测授权再限制总调用和费用。最终批次不发布 GitHub，去重结果留在内部；真实写闭环以 R1/R5 独立证据为准。ENGINEERING_READY 与 LIVE_READY 分开，未运行的 90 项只能是 NOT_RUN。

最终启动预检发现通用 authorization_budgets 的数据库 envelope 为 100，不能承载 270 次组额度（R4 应用许可本身仍是 24）。原启动在 INSERT 约束检查时回滚，未发生模型请求。采用追加迁移 0017，将最终评测组独立到 benchmark_budgets，并在 usage_calls 独立记录 final_budget_hash；已有 R4 group 字段和通用上限不变。已存在的最终组记录可无损迁移，旧财务记录保留。每次预占/结算仍使用 Engine 同一事务，270 次只适用于匹配 manifest 的评测专用许可。

用户随后明确批准新增费用最多 US$2、累计不超过 US$4，并明确允许把冻结的合成知识、合成 SQL 结果及公开 GitHub 源码证据发送到 DeepSeek 官方接口。本轮继续执行更低的冻结方案：最多 270 次、最高 US$1.658880、累计最高 US$1.687429，仍受代码中的 US$2 仓库硬上限约束。更高授权未被用来自动启动额外重跑或消融。第一次冻结候选零调用的 setup FAIL 保留，专用预算修复后使用新 manifest 执行相同题集。

最终实验中出现真实 OOM 进程中断。18 项结果、42 次已结算调用封存；由独立监督进程逐任务续跑，未结束的已启动任务记为基础设施失败，不重做，原财务组不重置。允许的源码变更仅覆盖监督/状态与延迟统计；通过旧源码归档的整体 SHA256 验证保护原取证、模型策略、Oracle 和题集。

在 24 项状态记录后，两笔预占发生 OSError 且没有落库回执。按冻结规则停止所有后续付费，保留 unknown 和 US$0.012288，不假定请求未发出。Engine 实际恢复请求已生成。之后的客户端初始化/I/O 防护属于新的工程版本，不回写旧模型成绩，不突破冻结源码校验。当时付费实验为 PARTIAL，项目不能标 LIVE_READY。

用户随后提供完整供应商小时聚合账单。13 次请求与已知 11 次及两次未知相符；同一 Run、profile 和财务组的差额为输入 613、输出 322 token，按冻结美元峰值及逐请求取整余量合计核账 US$0.000572。人民币账单没有直接当作美元；逐请求 token 仍未知，分配金额明确标为聚合记账。结算由 Engine 同一事务完成，审计原件存私有 CAS；不重发丢失响应，不退回调用次数，原案例仍 FAIL。然后仅继续原授权内未启动的 66 项，最终全部 90 项完成。

最终 A/B/C 分别通过 15/30、15/30、16/30，总计 46 PASS、44 FAIL。C 的正常 13/25、负例 3/5、引用 98% 未达冻结门槛，不能宣称多 Agent 优势或 LIVE_READY。本轮 195 次、保守 US$0.087980，累计 224 次、US$0.116529，预占和未知费用为零。工程基线 295 项及后续核账恢复专项 61 项通过（有重叠），不替代模型业务质量验收；R6 整体仍为 IN_PROGRESS。完整结果、限制和后续改进见 [交付报告](../r6-delivery.md)。
