# ADR0017：复用R4/R5的电商Case与独立结果实施

状态：实施，验收结果见[实施档案](../repairs/P0-20261106/README.md)。依据：用户要求实施已冻结的两项P0设计；不开展P1/P2。

在原Thread/Ticket/Run、Mandate、Action/Outbox之外，新增迁移0018保存模板、Case版本、阶段关联、幂等请求和不可变业务结果。Case不复制原执行状态；结果投影读取四种权威来源。原设计文档和历史实验结果不改写。

调查继续使用原R4图、工具授权和证据Verifier；Commerce提供注册来源与短引用ID适配。DataReader可显式绑定created_at，使时间窗列也参与数据集完整性hash；旧四列配置保持原含义。数值回执来自本Run实际typed行与SQL聚合，金额用Decimal计算，不读取设计夹具里的expected字段。

修复继续使用原R5图和沙箱，只接受原受限函数体。结果绑定准确调查hash；公开、独立与实际订单窗口测试为硬门槛。新Action附加business_result_hash/spec_hash，原payload审批和远端完整对象核对仍负责外部交付，不宣称跨系统exactly-once。

将报告与修复创建拆为事务外准备和内部SQL-only提交，原公开入口兼容。新结果、当前指针和原只读报告完成共用原Engine持锁连接的一次事务。发布前事务外核对CAS、沙箱与SQL来源，短验证租约绑定payload/Case/input/epoch；事务内重核当前结果、权限与租约。每个远端发布子步骤重新准备，不跨步骤借用旧证明。

原上下文evidence解析与动作列表曾在事务内间接读取CAS；边界注入测试发现后移到事务外。回执未知仍保留预占、停止后续任务并只读对账。新的业务记录不授予付费或外部写权限。

API/CLI/工作台复用原本地认证。当前权限撤销时隐藏旧结果正文；旧PASS不豁免来源权限。新输入、Case版本或epoch使旧结果不适用；取消后晚到远端回执只保留事实，不恢复任务。
