# ADR 0002：R2 安全点输入与可恢复只读任务

R0/R1 于 2026-11-02 通过工程复验和真实模型/GitHub 验收后实施。R1 摘要为 `docs/acceptance/r1-live-20261102.json`。

新 Run 使用 `r2-mailbox-v1`；已有 R1 Run 保留原图版本。Engine 仍是唯一业务写者。图的 intake 先保存不可变输入快照，checkpoint 后的 replan 才幂等确认消费游标。两次写入不假装原子；重入任一节点都从业务快照恢复。新评论只追加，原始 question 不被后台覆盖。

每个调查、验证和工具节点之后回到 intake。一个 Run 最多接收三个不同输入版本的调查快照（初始加两次 replan），付费步骤按输入版本去重且仍受既有 profile 总预算约束。工具完成消息推进序号，不增加用户输入版本或付费次数。超限保留未消费输入并进入 waiting_input，不自动扩大权限。

长只读任务有持久 job 和领取 lease；读取在线程中执行，完成后由 Engine 同事务提交 Artifact 引用、tool_result 事件和 Mailbox。图等待该结果，API、调度循环和控制请求保持可用。启动只重放只读任务，旧 lease/epoch 的迟到结果被拒绝。外部写仍只走 Action/Outbox/Dispatcher，unknown 仅对账。

暂停先持久化状态并提升 epoch；节点在边界停止。取消同样拒绝迟到结果。恢复不撤销远端已经完成的写，也不会绕过未知模型用量或未知外部写。后续输入使未发出的旧提案失效，新提案需要新的完整 hash 审批；已经发出的写先对账，再处理已接受的后续输入。

真实发布次数也按 profile 累计：默认最多一条结果评论，在途和 unknown 都占用额度。既有 R1 profile 哈希保持兼容，其一条评论额度已经使用；R2 不能复用它来增加发布次数。提高 `max_result_comments`（最多三条）会改变 profile 哈希，需要匹配的新授权。

Mailbox 上限 64 条待消费消息、64 KiB（为在途工具预留完成事件空间），输入快照上限 64 KiB。待消费消息七天过期后明确阻塞并保留，不静默丢弃。当前单 primary、确定性路由；没有 Router LLM、跨任务记忆或修复能力。R2 工程通过不等于 R3–R6 或生产就绪。
