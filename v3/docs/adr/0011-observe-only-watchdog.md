# ADR 0011：独立确定性 Watchdog 与 Engine 恢复请求

状态：首个工程切片实现。R5 的 249 项工程回归和真实 Draft PR 恢复均通过后启动；R6 整体仍为 IN_PROGRESS。

Watchdog 是独立 Python 进程，只访问两个受限本机 HTTP 入口：读取无正文、问题或凭据的状态快照，以及提交 RecoveryRequest。专用令牌与管理令牌分离；它不能批准动作、暂停 Run、调用模型、直接访问数据库或派发 Outbox。进程代码不加载 Settings/.env，运行入口清理继承环境。这里是受信运行组件的最小凭据配置，不声称它是操作系统沙箱。

PostgreSQL 仍由唯一 Engine 的持锁会话写入。迁移 0013 增加不可变观察事实及独立决策字段；Watchdog 经 Engine 提交请求，不成为第二写者。Engine 用当前 PG 事实、版本及 epoch 重新计算确定性信号，拒绝伪造或过期观察；并发或重复提交同一观察只保留一条请求。请求本身不推进 Run，也不改变进展游标。

本切片识别：运行/排队两分钟无持久进展、waiting_input/waiting_approval 一小时等待，以及 outcome_unknown。未知效果优先，取消后仍未确认的效果也可见。每次最多观察 256 项，超限明确返回 partial，不声称完整覆盖。阈值及检测版本固定，不由模型或外部文本改写。

管理令牌通过同一 API/CLI 显式决定 wait、escalate、pause 或 cancel。决定前重新核对事实；若工作已经推进，旧请求记 stale，不触发控制。暂停/取消调用既有 Engine 控制路径，与请求决策同事务提交，保留 epoch fencing。未知效果只允许等待或转人工，没有自动重发或继续发布入口。

只读查询失败时本轮没有提交请求；提交后的回执丢失则报告 unknown，不记为未保存。下一次巡检按相同观察键核对并去重，仍只涉及 Engine 内部恢复建议，不触发任何 Run 控制或外部 effect。

工程验收使用真实 PostgreSQL、独立进程和真实环回 HTTP，覆盖限权、幂等、旧 Worker 迟到、原子回滚和服务不可用。没有新增模型调用或真实业务发布。R6 后续仍需独立心跳/过期执行者、队列积压与依赖健康、主动策略 observe→有限 auto、只读投机独立预算，以及完整 A/B/C、故障矩阵和部署验收。
