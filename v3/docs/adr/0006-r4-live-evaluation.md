# ADR 0006：R4 真实调查、共享实验预算与冻结对照

状态：已实施。用户要求真实模型/GitHub/知识/SQL 调查、三个正常与两个不足/越权案例、独立判定及单 Agent 对照；随后明确授权新增最多 24 次调用，累计仍不超过 USD 2。

此前三次已耗尽的授权账本保持不变。新增实验授权绑定冻结 manifest、前序账本、身份、期限、调用数和累计金额；所有案例与方案的 profile 共享一个新增预算，同时保留原单任务预算。预占及结算由持有 advisory lock 的 Engine 在同一 PG 会话中原子更新，不把新增 profile 当作预算重置。未知模型请求保留预占并停止后续请求，不自动重发。

冻结输入、知识快照、RAG 配置、数据版本、GitHub commit、模型、价格、实现与独立 Oracle。Oracle 仅由可信验收器读取，不进入知识索引或模型请求。业务判定与机械引用验证分别记录，健康检查不替代业务结果。

本次比较固定只读工具计划。多专家包含 Knowledge/Repo 模型提取、实际 SQL 工具专家及模型综合；单 Agent 串行读取同源工具，以一次模型综合作答。数据为自有合成输入，GitHub 来源为锁定版本的真实应用代码。不把固定计划实验等同通用自主规划。

官方 GitHub MCP 的实际文件响应采用 TextContent 加 EmbeddedResource，适配器核对目标 URI、commit、路径及 Git blob 字节哈希。SQL 角色按数据库/项目/仓库/身份/数据版本分开，避免跨案例轮换使既有 reader 失效，同时限制 DB 级读取范围。角色凭据留在本地私有文件中。

来源提取与跨源业务问题分开。首轮 Repo 提取曾返回空 claims，补证据耗尽单任务三次额度，导致综合未执行。修复只收窄专家子问题，不改变业务输入或 Oracle；一次恢复以新 Run 共享原有实验预算，原 profile 与总计数均不重置。恢复只允许失败的 multi arm，保持题目/模型/数据/来源/单任务限制，并记录审计事件。原结果和恢复结果分开保存。

首轮双方各 4/5，不能宣称多专家优势。恢复后多专家五例均有通过记录，但首轮总体 FAIL 和单 Agent 的 null 字段失败保留，live 状态为 PARTIAL。模型解释单列，不升级为机械验证的事实；本次所有拟发布动作均取消，未发送 GitHub 业务评论。R5/R6 不在本次范围。
