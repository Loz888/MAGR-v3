# ADR 0009：补丁行数元数据规范化与已结算结果重放

状态：已实现，完整工程回归 248 项通过；真实发布验收待审批。增补 ADR 0007/0008；不扩大路径、AST、费用或发布权限。

2026-11-03 的冻结 R5 实验实际消耗三次 DeepSeek 调用。原始补丁分别在格式或原文定位检查失败，没有执行候选测试或创建 PR。这一实验保持 FAIL，不能把后续修复后的重测算作原始成功。

第一个输出的代码内容满足待测契约，但 hunk 的旧行数声明是 8，实际为 9。`recount_diff` 只按已有上下文、删除行和新增行重算 hunk 声明的数量，保留路径、起始位置和全部代码字节。它不移动 hunk，不修复上下文，不生成代码。规范化后仍执行原有精确应用、路径与 AST 校验，以及真正的公开/独立隐藏 Go 测试。输出大小和行数上限不变。

原始模型结果和账本不变。Engine 新增不可混淆的 normalization 步骤，记录算法版本及原始/规范化 diff 的 SHA256；完整提案同时绑定这些哈希、模型 call_id、来源 Run、profile、实际文件内容和测试回执。

原 Run 的期限已经过去时，不延长期限、不清空次数、不覆盖原试验。显式恢复实验可创建独立 Run，使用 `RecordedPatcher` 读取同一冻结 profile、来源 Run、输入版本和步骤上已经结算的结果。源码、问题和 profile 必须一致；找不到已知结果就停止该候选，没有 HTTP 或付费回退。新 Run 仍有独立的原定修复期限，重新执行基线与候选测试，仍须批准最终完整提案。profile 与累计组中的三次调用已经耗尽，不能因重放获取新额度。

提案的模型来源核对使用相同的不可变 profile，而不强制来源 Run 与当前 Run 相同；同时验证规范化结果逐字等于最终 diff，并在 payload 中显式记录来源 Run。人工编辑仍通过原有显式输入记录与重测流程。

真实恢复实验只使用第一个已结算输出，把 `@@ -7,8 +7,16 @@` 变为 `@@ -7,9 +7,16 @@`，公开测试和独立 Oracle 的 28 个隐藏子案例通过。重放前后账本相同：三次调用，US$0.001524，预留为零。真实 PR 的创建与回执恢复仍以最终发布记录为准；这些测试不等同任意仓库修复能力。
