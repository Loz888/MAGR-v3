# ADR 0010：过期提案的显式重新审阅

2026-11-03 用户在完整提案原有效期结束后明确回复“批准完整提案”。本次授权仍针对相同的完整 payload、仓库、基础提交、文件内容、分支、标题、正文和 Draft PR 数量；不能因为操作员等待而自动发布，也不需要对已经明确批准的同一内容重复索取授权。

追加迁移 0012 保存单独的 `action_review_renewals` 审阅记录，绑定原 action_id、完整 payload_hash、批准人、当前审阅时间及新的短有效期。原 Action、原到期时间和 payload 均不修改；续签记录在 PostgreSQL 中不可更新或删除。Action 查询同时返回当前审阅到期时间。

只有经过授权的操作员显式调用 `renew_review` 才可续签。限于完全未发送、尚无审批或 Outbox/发布子步骤的 Draft PR；哈希必须相同。重新验证原有版本、epoch、primary、目标写权、Mandate 和独立测试证明；所有其他门禁保留。续签本身不批准 Action、不创建 Outbox、不调用模型、不访问远端。重复调用只返回已有有效记录，不滚动延长有效期；第二次到期必须重新提案。

默认审批和发送仍拒绝过期 Action。显式人工审阅续签后，现有 Engine 审批/Outbox/Dispatcher 协议使用审阅记录的有效期；源代码基线仍在每个真实远端写之前读取核对。响应未知和已发送动作不能通过续签重发。

操作员发布工具只在明确提供 `--renew-expired-proposal` 时申请续签；该参数不能代替用户对准确完整提案的批准。Watchdog 和普通 Worker 不调用此入口。本次 R5 不新增模型调用，原三次额度已耗尽。
