# V35-E01：重建端到端真实仓库评测 Harness

- 状态：DONE（2026-11-10）
- 依赖：V35-R05、V35-M01
- 优先级：P1
- 涉及文件：`quality_eval/`、新建 `quality_eval/v35/{tasks,runner,grader}.py`、`scripts/run_eval.py`、新 `tests/test_v35_e01.py`

## 目标

评测真实产品链路，不是单次 Prompt。统一 Harness 覆盖三种任务（已知问题修复、回归仓储调查、多文件小功能）与真实唯一 Holdout。

## 执行要点

1. 每个任务固定仓库、Commit、问题描述、初始失败、隐藏验证、预算与成功判据。
2. 驱动 `create/run/patch/test/verify` 真实接口与真实沙箱；评分只读最终 Commit/人工固定 Diff/隐藏测试结果。
3. 防污染：开发样例与 Holdout 分开，Holdout 不参与提示词、规则或离线自测。
4. 评分：问题复现、正确修复、回归、无关变更、越界路径、成本、模型调用数、修复/发布正确性；失败与不可复现分开。
5. 新增 At least one adversarial/多轮/断点恢复任务；不伪造 Live 结果。

## 验收

- 公开开发集可复现评分；Holdout 只在评测时运行；区分 `fixture` 与 `live` 两套结果。
- `tests/test_v35_e01.py` + 保留 E01 历史报告；不覆盖旧评测数据。
- `engineering_gate` 与 `live_agent_gate` 相互独立，必须分别记录，见下方强制验收协议。

## 实现

### 1. 数据集与防污染（`quality_eval/v35/tasks.py`）

- 开发集 4 个任务，覆盖三类：`known_bug_fix`（help name 冲突）、`regression_investigation`（短帮助缩写误截断）、`multi_file_feature`（缩写与占位符跨 `utils.py`/`core.py`）、adversarial（首补丁只改一半，公开测试失败后依据反馈二次修复）。
- 每个任务固定真实仓库（pallets/click）、base/gold commit、快照目录与 digest、公开/隐藏测试列表、允许路径、预算（3 attempts / 4 model calls / 8 test runs / 600s）与成功判据（公开+隐藏双通过、0 无关变更、0 越界路径、禁止发布）。
- 快照 digest 排除 `__pycache__`/`.git`/`.mypy_cache`/`.pytest_cache`/`.pyc`，加载时逐文件校验；`load_development` 永不读取 holdout，holdout 只在显式 `--evaluate-holdout` 时加载，且与 dev 资产路径不重叠。
- 唯一真实 Holdout 为 `v35-holdout-envvar-sequence`（独立 commit 与快照），开发提示词、规则与离线自测均不包含它。

### 2. 真实执行链（`quality_eval/v35/runner.py`）

- `create`：字节级快照 + 真实 Docker 沙箱跑 baseline，必须得到 `test_failed` 且失败测试与固定列表一致，否则判 `not_reproducible`。
- `run`：`AuthorizedRepairOrchestrator` + `SnapshotRepairRuntime` + R03 `SandboxExecutor`（固定镜像、`network none`、非 root），逐个 `PatchPlan` 走 R02 `PatchWorktree` 的文件授权与 patch limits（4 文件 / 400 行 / 512KiB 单文件）。
- `patch/test`：公开测试通过后运行独立隐藏验证；尝试记录写入 `JsonRepairLedger` 检查点。
- `verify`：只生成 sealed Review Bundle 并停在 `waiting_approval`，评测禁止发布 Draft PR；评分只读最终 diff、receipt 与隐藏结果。
- 断点恢复：把检查点重开为 `proposing` 并复制 ledger，`ForbiddenProvider` 证明恢复过程不再调用模型（`provider_calls=0`），不重复已完成的工具/测试工作。

### 3. 评分与门禁分离（`quality_eval/v35/grader.py`）

- 维度：复现、公开/隐藏、正确修复、无关变更、越界路径、模型调用数、token/费用/延迟、发布正确性（bundle diff hash 与 proposal 一致、`base_sha` 一致、未执行发布）。
- `classify` 区分 `pass`、`not_reproducible`、`infrastructure_error`（依赖缺失/沙箱错误）与业务 `fail`，失败样本原样保留。
- `summarize` 只聚合单一 mode：fixture 的 `live_agent_gate` 恒为 `NOT_RUN`；summary 不含 Holdout 合并。
- 顶层 `attempts` 与 `score_signature` 只覆盖决策相关字段（状态、公开/隐藏、变更集合、尝试数），忽略时间与随机 id，便于复核重跑一致。

### 4. CLI 与依赖检测修正

- `scripts/run_eval.py`：`--suite dev|holdout`、`--mode fixture|live`、`--task`、`--out`；live 无授权文件或 provider 时写出 `NOT_RUN` 报告，绝不伪装；holdout 需显式开关；报告目录不允许覆盖旧结果。
- `repair/sandbox_executor.py` 的 `PythonAdapter` 只统计模块级运行时 import，跳过函数体内 lazy import 与 `if TYPE_CHECKING:` 分支；模块级真实第三方依赖仍触发 `waiting_for_dependencies`。

## 负向测试

- baseline 若在快照上通过 → `not_reproducible`；依赖缺失/沙箱错误 → `infrastructure_error`，与业务失败分开。
- 隐藏验证文件绝不出现在模型可见文件或提示词中（provider 侧断言 `verification/` 泄漏即失败）。
- 越界路径与无关变更即使测试通过也判 `fail`；多文件任务少于两个文件不通过。
- live 模式缺少授权文件或 provider 时只写 `NOT_RUN`，fixture 结果不得进入 `live_agent_gate`；报告目录已存在时拒绝覆盖。
- Holdout 默认不加载、不参与 dev 自测；开发集永不读取 Holdout 资产。

## 边界与未完成项

- 未调用付费模型、未执行真实 Agent 长任务：`live_model_gate` / `live_agent_gate = NOT_RUN`；fixture 只证明执行链与评分正确，不代表真实 Agent 能力。
- 未执行真实 GitHub 读写：`live_github_write_gate = NOT_RUN`；评测中发布保持 `waiting_approval` 且禁止执行。
- Holdout 已构建并在直接沙箱检查中验证「base 失败 / gold 通过」，但按防污染规则未在任何 E01 evidence 运行中执行；真实 Holdout 运行留给后续真实模型评测或单独授权的执行。
- 数据集原计划使用 Python 3.12 特有的 Enum sentinel 缺陷，但固定 R03 镜像为 Python 3.11.2（按名字 pickle，缺陷不复现），因此改用与解释器版本无关的 help-name / short-help / placeholder 缺陷；该调整不降低任务形态覆盖。
- 为了让真实快照可直接运行，`PythonAdapter` 的依赖检测从「任意 import」收紧为「模块级运行时 import」；这是本卡唯一的产品代码改动，已由 `tests/test_v34_sandbox_executor.py` 回归覆盖。

## 强制验收协议（2026-11-10 补充，不可裁剪）

真实 Agent 评测必须**同时**满足以下条件：

1. 使用真实模型 API，而非 `FixtureModel` 或 `ScriptedProvider`。
2. 使用统一 Workbench 与实际 Agent Runtime，不允许另写独立单轮评测脚本绕过执行链路。
3. 完整记录每轮 `Reason`、`Tool Call`、`Observation`、`Patch`、`Test`、`Feedback` 和 `Retry`。
4. 必须包含至少一个第一次修复失败后，Agent 根据测试反馈自主生成第二版补丁的测试场景。
5. 修复成功必须同时通过公开测试与独立隐藏测试；失败样本保留。
6. 最终提供真实模型执行成功率、平均调用次数、费用、延迟和失败原因统计。

验收状态必须独立：

- `engineering_gate = PASS` 不代表 `live_agent_gate = PASS`。
- 未执行真实模型实验时，必须标记 `live_agent_gate = NOT_RUN`，不得宣称已完成真实 Agent 能力验收。
- `fixture` / `ScriptedProvider` / 离线回放结果只能计入 `engineering_gate`，不得计入 `live_agent_gate`。
- `live_agent_gate = PASS` 必须能由 `accept/V35-E01/accept.json` 指向的真实模型运行证据、逐轮轨迹与第 6 项统计直接复核；缺失任一条即判 `FAIL` 或 `NOT_RUN`，不得以“工程门已通过”替代。
