## 目标

评测真实产品链路，不是单次 Prompt。统一 Harness 覆盖三种任务（已知问题修复、回归仓储调查、多文件小功能）与真实唯一 Holdout。

## 执行要点

1. 每个任务固定仓库、Commit、问题描述、初始失败、隐藏验证、预算与成功判据。
2. 驱动 `create/run/patch/test/verify` 真实接口与真实沙箱；评分只读最终 Commit/人工固定 Diff/隐藏测试结果。
3. 防污染：开发样例与 Holdout 分开，Holdout 不参与提示词、规则或离线自测。
4. 评分：问题复现、正确修复、回归、无关变更、越界路径、成本、模型调用数、修复/发布正确性；失败与不可复现分开。
5. 新增 At least one adversarial/多轮/断点恢复任务；不伪造 Live 结果。

## 验收

- 公开开发集可复现评分；Holdout 只在评测时运行；区分 `fixture` 与 `live` 两套结果。
- `tests/test_v35_e01.py` + 保留 E01 历史报告；不覆盖旧评测数据。
- `engineering_gate` 与 `live_agent_gate` 相互独立，必须分别记录，见下方强制验收协议。

## 强制验收协议（2026-11-10 补充，不可裁剪）

真实 Agent 评测必须**同时**满足以下条件：

1. 使用真实模型 API，而非 `FixtureModel` 或 `ScriptedProvider`。
2. 使用统一 Workbench 与实际 Agent Runtime，不允许另写独立单轮评测脚本绕过执行链路。
3. 完整记录每轮 `Reason`、`Tool Call`、`Observation`、`Patch`、`Test`、`Feedback` 和 `Retry`。
4. 必须包含至少一个第一次修复失败后，Agent 根据测试反馈自主生成第二版补丁的测试场景。
5. 修复成功必须同时通过公开测试与独立隐藏测试；失败样本保留。
6. 最终提供真实模型执行成功率、平均调用次数、费用、延迟和失败原因统计。

验收状态必须独立：

- `engineering_gate = PASS` 不代表 `live_agent_gate = PASS`。
- 未执行真实模型实验时，必须标记 `live_agent_gate = NOT_RUN`，不得宣称已完成真实 Agent 能力验收。
- `fixture` / `ScriptedProvider` / 离线回放结果只能计入 `engineering_gate`，不得计入 `live_agent_gate`。
- `live_agent_gate = PASS` 必须能由 `accept/V35-E01/accept.json` 指向的真实模型运行证据、逐轮轨迹与第 6 项统计直接复核；缺失任一条即判 `FAIL` 或 `NOT_RUN`，不得以“工程门已通过”替代。
