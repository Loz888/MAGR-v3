## 目标

保留现有四类 Memory 契约与 `knowledge.memory_*` 表；把 R04/R05 的进程内 `EpisodeSink` 适配为持久 `MemoryWriter`。

## 执行要点

1. 不新建第五个同功能 Store。
2. 记录失败补丁类型、测试原因、验证结果、发布回执与可复用策略。
3. 只有通过来源/密钥/Prompt Injection 校验的候选才能持久化；Semantic/Procedural 升级采用既定人工确认策略。
4. 建立 `Task/Run → Finding → Evidence → RepairAttempt → TestReceipt → Memory` 可追溯链；历史 Commit 经验标记 `requires_reverification`。
5. 召回先 ACL/项目/仓库过滤，再按任务/Commit 相关性检索；模型只获得参考性、带来源的摘要。
6. 写入失败要审计并可重试，不得破坏已验证业务状态或静默丢经验。

## 负向测试

错误项目/仓库、已撤销记忆、跨 Commit 误认、含密钥/注入内容、低置信无证据、重复写入。

## 验收

- 一次修复的失败与成功经验能在新 Run 中安全检索，Evidence ID 可回溯；工作记忆不跨任务冒充事实。
