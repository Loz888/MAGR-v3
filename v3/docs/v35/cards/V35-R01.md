## 目标

实现生产级 `RepairProvider.propose(RepairPrompt) -> PatchPlan`：从模型结构化 JSON 严格校验为 `FileEdit(path, operation, expected_sha256, content)`，绝不执行模型 Shell 文本。

## 执行要点

1. Prompt 只含最小目标源码片段、只读证据、允许路径、失败测试摘要与最新文件 SHA；不得暴露隐藏测试。
2. 校验文件存在性、相对路径、权限、保护文件、变更行数/字节、版本前置条件；拒绝新增依赖清单与隐式扩围。
3. `PATCH_STALE`、格式不合规、内容无效返回机器可读反馈；预算内允许重新读取真实文件后再提案，不重复已未知结果的工具。
4. Unified Diff 仅作审查输出；不把模型 Hunk 行号当作变更事实。
5. 记录真实 Token/费用、解析错误与结构化补丁成功率；敏感内容脱敏。

## 负向测试

错误 JSON、输出截断、无 Usage、路径逃逸、文件 SHA 过期、补丁超预算、修改 `.git`、正文夹带命令。
