# V35-R01：结构化模型补丁提供方

- 状态：DONE（2026-11-10）
- 依赖：V35-U02
- 优先级：P0
- 涉及文件：`repair/repair_agent.py`、新建 `repair/providers/{__init__,structured}.py`、`repair/worktree.py`、新 `tests/test_v35_r01.py`

## 目标

实现生产级 `RepairProvider.propose(RepairPrompt) -> PatchPlan`：从模型结构化 JSON 严格校验为 `FileEdit(path, operation, expected_sha256, content)`，绝不执行模型 Shell 文本。

## 实现

### 1. 严格 JSON → 全文件补丁

`StructuredPatchProvider` 只接受一个 JSON 对象：

```json
{"summary": "...", "edits": [{"path": "...", "operation": "update|create|delete",
 "expected_sha256": "...", "content": "完整替换文本"}]}
```

- `content` 必须是完整文件内容，不接收 `diff` / `patch` / `hunks` / 行号；模型给出的 Unified Diff 仅可作为审查文本，不能作为变更事实。
- 顶层与每条 edit 的未知键一律拒绝；`command` / `shell` / `argv` / `exec` / `script` 等命令字段返回 `PATCH_COMMAND_REJECTED`，提供方不存在任何执行模型文本的代码路径。
- `update` / `delete` 必须携带与 Prompt 中最新文件 SHA 一致的 `expected_sha256`；`create` 只能用于当前不存在的路径，且必须由 `PatchLimits.allow_new_files` 放行。

### 2. Prompt 最小化与隐藏测试隔离

`RepairPrompt` 新增 `allowed_paths` 与 `limits`；提供方构造的模型载荷只包含：

- `objective`、`language`、`attempt` / `max_attempts`、已有 `feedback`；
- `allowed_paths` 与其中每个文件的最新 `sha256` 和内容；
- 缺失路径列表与响应 schema。

`verification_files` 不属于 `RepairPrompt`，因此隐藏测试在结构上无法进入模型上下文；测试 `test_prompt_is_minimal_and_never_contains_hidden_verification` 对载荷做了断言。

### 3. 校验顺序

1. Prompt 输入字节上限（默认 262144）；
2. 路径：相对路径、无 `..`、无隐藏段（含 `.git`、`.github`）；
3. 授权：必须在 `allowed_paths` 内；
4. 保护文件：依赖清单、配置与锁文件由 `PatchLimits.protected_globs` 拒绝（即使 allowed_paths 显式包含）；
5. 存在性与操作前置条件：`create` 冲突 / `update`、`delete` 缺失；
6. 版本前置条件：SHA 不一致返回 `PATCH_STALE`（可恢复）；
7. 内容与预算：NUL、单文件字节、总字节、变更行数、文件数、删除数；
8. 类型与 schema；全部失败均返回机器可读 code 与 `retryable`。

校验复用 `worktree.py` 中同一组函数（`validate_patch_path`、`is_protected_path`、`validate_patch_content`、`line_delta`、`sha256_text`），避免提供方与真正应用补丁的工作区出现两套语义。

### 4. 机器可读反馈与不重复未知调用

- 提供方抛出 `PatchProposalRejected(code, retryable, details)`；`RepairAgent` 将其转成 `RepairFeedback(stage="patch", code, message)`，在预算内重新读取工作区真实文件并进入下一轮提案。
- `retryable=False`（无 Usage、未知调用结果、输入超限、模型接口不可用）立即停止，状态为 `provider_error`，不会盲目重试。
- 对同一 `(repository, objective, attempt)`，若上一次付费调用结果未知或 Usage 缺失，后续 `propose` 直接返回 `PATCH_OUTCOME_UNKNOWN`，不再发送模型请求。

### 5. 真实用量与脱敏统计

- 模型回复必须包含 `usage.prompt_tokens` / `usage.completion_tokens`；缺失时拒绝，不记成功。
- `ModelPricing` 可按输入/输出每百万 token 价格推导费用；回复自带 `cost_micros` 时优先使用。
- `ProviderStats` 汇总调用数、接受/拒绝数、解析错误、未知结果、Token、费用与结构化补丁成功率。
- `ProviderCall` 只记录 attempt、code、Token、费用、延迟、回复哈希与 edit 数，不保存 Prompt、源码或模型正文。
