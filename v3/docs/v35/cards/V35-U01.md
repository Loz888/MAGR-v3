# V35-U01：统一 Task / Run Ledger 与状态迁移

- 状态：READY
- 依赖：V35-B00
- 优先级：P0
- 涉及文件：`workbench/{domain,store,service}.py`、`coordination/engine.py`、必要的 `migrations/0023_*.sql`、新 `tests/test_v35_u01.py`

## 目标

保留 `audit / issue_repair / audit_and_repair` 三个用户意图，用同一 Task ID 关联 `audit_run_id / repair_run_id / verifier_run_id`；引入 Append-only 事件与服务端状态校验。

## 执行要点

1. 显式阶段：`queued → investigating → suspected → reproduced → repairing → patch_verified → waiting_approval → publishing → pr_created`，加 `paused / failed / cancelled / waiting_input`；不得跳级。
2. 统一幂等键、乐观版本/CAS、Epoch Fence；旧 Worker 不得提交新状态。
3. 保持旧 `repo-analysis` 与 R5 API 兼容；迁移只允许前向追加（从 `0023` 起）。
4. Workbench 全局写入收敛到 Engine 授权的事务边界；Agent 不直接改 Task 状态。

## 负向测试

重复创建任务、相同请求 ID 不同 Payload、两个 Worker 同时推进、旧 Epoch 回写、取消后继续发布、未批准跳至 `pr_created`。

## 验收

- 状态转移 100% 由服务端校验；并发场景只产生一份合法状态与事件。
- `tests/test_v35_u01.py` + `tests/test_v34_repository_api.py` + `tests/test_v32_repository_analysis.py`，真实 PostgreSQL。

## 禁止

- 新建平行状态机；用 mock 数据库替代真实 PostgreSQL；删除既有回归
