## 目标

统一 Investigation 与 Repair 的模型输入预算；压缩不得改变权威约束、Evidence 或 Tool Receipt。

## 执行要点

1. 分别计量 System、Task、权限约束、计划、Recent Observations、Evidence IDs、相关 Memory、失败历史。
2. 硬约束（仓库/Commit、允许工具、审批、预算、Evidence/Artifact Hash、未完成动作）不得因压缩改变或丢失。
3. 结构化 Context Bundle 同时用于 Investigation 与 Repair，避免各写一套截断规则。
4. 评测现有确定性 Compactor；确有必要才加版本化后台 Compaction（冻结 `context_revision`、摘要、CAS 激活、Delta Replay）。
5. 压缩结果不得覆盖权威业务状态、原始 Evidence、原始 Tool Receipt；摘要失败降级到安全短窗口。
6. 统计 `input_tokens`、`context_size`、信息丢失校验失败、延迟与成本；对比压缩前后正确性。

## 负向测试

压缩期间新 Tool Result 到达、摘要含伪授权、旧 Revision 覆盖新事件、摘要遗漏待审批/失败证据、Token 预算极小、Artifact Hash 变化。
