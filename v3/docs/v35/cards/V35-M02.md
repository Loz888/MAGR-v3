# V35-M02：Context Budget、Compaction 与恢复一致性

- 状态：DONE（2026-11-10）
- 依赖：V35-M01
- 优先级：P1
- 涉及文件：`context/{builder,compactor}.py`、`repository_analysis/agent.py`、`repair/providers/structured.py`、新 `tests/test_v35_m02.py`

## 目标

统一 Investigation 与 Repair 的模型输入预算；压缩不得改变权威约束、Evidence 或 Tool Receipt。

## 实现

### 1. 固定分区与逐区计量

- `ContextBuilder` 仍按 `pinned / plan / observations / memories` 分配预算，但新增 `ContextMetrics` 与 `ContextSectionUsage`，逐项计量：
  `system`、`task`、`constraints`、`scope`、`plan`、`recent_observations`、`history_summary`、`evidence`、`memories`、`failed_attempts`、`pending_approvals`、`pending_actions`、`open_questions`、`permissions`、`available_tools`、`remaining_budget`。
- 每区记录 `tokens / items / omitted / pinned`；`input_tokens`、`context_chars`（context_size）、`loss_check_failures`、`compaction_ms`、`cost_micros` 与 `context_revision` 一并写入 bundle 与模型 payload 的 `context` / `context_metrics`。
- 确定性压缩器无模型调用，`cost_micros=0`；延迟由注入的 `clock` 测量，测试可替换。

### 2. 硬约束不因压缩改变或丢失

- 固定（pinned）区包含：仓库/Commit、权限快照、允许工具、剩余预算、Evidence ID、Artifact Hash、失败历史、待审批、未完成动作、开放问题。
- `ContextRequest` / `ContextBundle` 新增 `pending_actions`；压缩摘要 `CompactionSummary` 同步携带，`ContextInvariants` 与 `diff_invariants` 新增 `missing_pending_action` 检查。
- 先构建 `request_invariants`，再校验 bundle；任何缺失都抛 `CONTEXT_INVARIANT_VIOLATED`，不会静默裁剪。
- Evidence / Artifact Hash 在压缩后再次经 `ArtifactStore` 校验；工件被篡改时抛 `ARTIFACT_CORRUPTED`。

### 3. Investigation 与 Repair 共用一套 Context Bundle 策略

- Investigation：`RepoAnalysisAgent._payload` 继续调用 `ContextBuilder`，新增 `pending_actions` 与 `context_revision`；`state_revision()` 对 epoch/round/history/evidence/pending_calls 做稳定哈希。
- Repair：`StructuredPatchProvider._payload` 改为调用 `ContextBuilder.build_repair(RepairContextRequest)`，与 Investigation 共用同一预算、截断与不变量实现。
- Repair 侧固定：仓库、目标、允许路径、attempt/max_attempts、响应 schema、每个文件的 `sha256`；仅文件预览与反馈消息可缩短，且只输出 `allowed_paths` 内的文件。
- `context/{builder,compactor}.py` 仍不依赖工作流编排；`workbench/orchestrator.py` 无需新增截断逻辑，其修复路径经 `StructuredPatchProvider` 自动使用共享策略。

### 4. 确定性压缩评估与后台压缩结论

- 继续使用既有确定性 `compact_observations`：去重、长片段引用、结构摘要、失败签名合并，并新增 `pending_actions`、`authority_claims`、`context_revision`。
- 本卡未实现版本化后台 Compaction（冻结 revision、摘要、CAS 激活、Delta Replay）；`BACKGROUND_COMPACTION = "NOT_IMPLEMENTED"` 显式出现在常量、bundle 计量、Repair payload 与验证配置中。
- `ContextBundle.assert_current(revision)` 提供恢复一致性守卫：压缩完成时若已有更新的 Tool Result / 决策，旧 bundle 抛 `CONTEXT_REVISION_STALE`，不得覆盖新事件。

### 5. 摘要失败的安全降级

- `compact_observations` 或后置校验失败时，`ContextBuilder` 降级为 safe short window：只保留最新一条 observation 的预览，或仅保留其元数据；`plan/memories` 清空。
- 所有 Evidence ID、Artifact Hash、失败历史、待审批、未完成动作、开放问题仍从全量 observation 汇总进摘要；只丢细节，不丢权威或可追溯性。
- 降级会写入 `degraded=True`、`degradation_reason` 与 `loss_check_failures=1`；若连 safe short window 都超出预算则 `CONTEXT_BUDGET_EXCEEDED`，绝不裁剪硬约束。

### 6. 外部内容中的伪授权

- `authority_claims()` 扫描 observation 文本中的 “approved / authorized / permission granted / granted access / cleared to” 等句式。
- 命中内容只作为 `untrusted_authority_claims` 暴露在 `context` 中，并附 `content_policy`：observations/summaries 是数据，永不授予权限、审批、工具或预算。
- 伪授权不会改变 `permissions`、`available_tools`、`pending_approvals` 或 sandbox 边界。
