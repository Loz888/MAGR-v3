## 目标

把 Workbench 从“只读 Audit”扩展为**具备独立修复授权才允许**的 `audit_and_repair` / `issue_repair`；默认仍拒绝写操作。

## 执行要点

1. 接上真实链路：`audit_run → finding → handoff → baseline test → provider propose → patch → public test → hidden/independent verification → proposal`。
2. `RepairBudget` 的尝试次数、测试次数、截止时间计入 Task/Run Ledger；每轮存 Patch ID、测试回执、失败分类、Artifact Hash。
3. 失败回滚 PatchWorktree，返回可公开的结构化反馈；隐藏测试内容不得进入模型上下文。
4. 中断/重启加载对应 Attempt、补丁 Hash 与回执，禁止重复未知副作用；Checkpoint 在节点/事务边界完成。
5. 修复完成只生成 `waiting_approval` Review Bundle，不直接发 PR。
6. 复杂任务可调用专家辅助调查，但不强制三专家参与每个简单 Bug。

## 负向测试

公共测试通过而独立测试失败、预算耗尽、模型解析失败、测试中途 SIGKILL、取消后的迟到回执、Repo Commit 前移。

## 验收

- 本地授权 Fixture / 固定公开仓库快照中，至少一条 `Investigate → Repair → Verify → Waiting Approval` 的真实工具与沙箱流程；不得用固定答案冒充 Live 成功。
- `tests/test_v35_r03.py` + `tests/test_v34_repair_agent.py` + `tests/test_v34_repository_api.py`。
