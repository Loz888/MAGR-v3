# V35-R04：把真实 Draft PR 发布接入 Outbox/Dispatcher

- 状态：TODO
- 依赖：V35-R03
- 优先级：P0（真实写权限为独立审批门）
- 涉及文件：`repair/pr_delivery.py`、`effects/`、`coordination/engine.py`、`workbench/{service,store}.py`、`api.py`、新 `tests/test_v35_r04.py`

## 目标

复用 R05 `ReviewBundle + PublicationApproval`，把发布统一到 Engine 审批的 Action/Outbox/Dispatcher；Workbench HTTP 请求内不得直接调用 GitHub 写 API。

## 执行要点

1. 审批绑定 repository、base Commit、tested Tree、Diff SHA、完整文件内容与 Payload Hash。
2. 读写 Token 分离；首次写前复查 base SHA；顺序为 branch → commit → Draft PR（不 merge）。
3. 步骤回执写 PG；结果未知时只读对账，查不到也不得盲目重试。
4. 每个审批/Action/Proposal 有稳定幂等键；相同审批并发只发布一次；撤销或 Payload 变化即失效。
5. 无 GitHub 写授权时输出完整 Patch/Bundle，状态为 `exported` 或 `waiting_approval`，不得声称已发布。

## 负向测试

Payload 变更、base 前移、重复审批、写 API 超时且远端已成功、Token 只读、写权限撤销、并发两次发布。

## 验收

- Mock/内存 transport 下无重复 PR；真实 GitHub Draft PR 必须在单独 `live_github_write_gate` 且用户明确授权的测试仓库进行，否则 `NOT_RUN`。
- `tests/test_v35_r04.py` + `tests/test_v34_pr_delivery.py` + 现有 Dispatcher 恢复测试。
