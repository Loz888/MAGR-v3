# V35-R04：把真实 Draft PR 发布接入 Outbox/Dispatcher

- 状态：DONE（2026-11-10）
- 依赖：V35-R03
- 优先级：P0（真实写权限为独立审批门）
- 涉及文件：`repair/pr_delivery.py`、`effects/`、`coordination/engine.py`、`workbench/{service,store}.py`、`api.py`、新 `tests/test_v35_r04.py`

## 目标

复用 R05 `ReviewBundle + PublicationApproval`，把发布统一到 Engine 审批的 Action/Outbox/Dispatcher；Workbench HTTP 请求内不得直接调用 GitHub 写 API。

## 实现

### 1. 持久化发布 Outbox（migration 0025）

- 新增 `app.workbench_publications`：`task_id`/`finding_id`/`execution_mode`、`repository`、`base_branch`、`base_sha`、`tree_hash`、`proposal_id`、`branch`、`payload_hash`、`diff_sha256`、`approval_id`、`actor`、`approved_at`、完整 `bundle`、`status`（`ready/dispatching/succeeded/failed/outcome_unknown/exported/stale/cancelled`）、原因、外部 ID、PR JSON、attempts、下一次重试时间与租约字段。
- 新增 `app.workbench_publication_steps`：`ordinal 0..2` 对应 `branch → commit → pull_request`，记录 `request_hash`、`status` 与远端回执 JSON。
- 稳定幂等键为 `UNIQUE (task_id, finding_id, payload_hash)`；同一审批重复入队返回同一行。
- 独立表而非复用 `app.actions` 的原因：`app.actions.run_id` 强制引用 `app.runs`，Workbench 任务没有 Engine run；表语义与既有 Action/Outbox 对齐（claim/lease/result/reconcile/recover）。

### 2. 审批绑定与请求内只入队

- `WorkbenchPublicationLedger.enqueue()` 先 `verify_approval()`：`approval_id` 必须由 actor、repository、base SHA、tree hash、payload hash、diff SHA-256 与批准时间共同内容寻址；bundle 的内容寻址 `payload_hash` 必须自洽；repository 必须一致；`bundle.base_sha` 必须等于任务快照 commit。
- `WorkbenchService.approve()` 现在只做三件事：推进 finding 到审批态、把发布以 `ready`（有独立写授权）或 `exported`（无写授权）写入 outbox。`live` 模式下 HTTP 请求不调用任何 GitHub 写 API。
- `fixture` 模式保持原行为：请求内用内存 transport 驱动同一个 `PublicationDispatcher.tick()`，因此既有 `test_v34_repository_api.py` 的同步 `pr_created` 断言不变。

### 3. 独立读写与写前复查

- `PublicationWriteScope(actor, repository, reader, writer, expires_at, base_branches, revoked)` 绑定 actor、仓库、允许的 base 分支、有效期；`revoke()` 后任何写入前校验都拒绝。
- `WorkbenchDraftTransport.send()` 顺序：内容寻址校验 → `verify_approval` → `DraftPRPublisher.review`（完整 diff 与文件）→ scope 校验（撤销/过期/仓库/分支）→ `writer.scope == "write"` 检查 → **base SHA 复查** → branch → commit → Draft PR。
- 读写 transport 分离；只读凭据在写入前以 `GITHUB_WRITE_SCOPE_REQUIRED` 拒绝，不产生任何远端写。
- 只创建 Draft PR，从不 merge。

### 4. 步骤回执与未知结果对账

- 每个远端步骤先 `begin_step()`（行锁校验租约，已成功则跳过，已派发则视为未知），成功后写回执；回执写失败升级为 `PublicationUncertain`，避免“远端已写而本地无回执”被重放。
- `Engine.claim_publication()` 使用 `FOR UPDATE SKIP LOCKED` + 5 分钟租约 + attempts 递增；`publication_result()` 校验租约后落终态；`reconcile_publication()` 只接受 `outcome_unknown` 且必须提供只读查到的外部 ID。
- `Engine.recover()` 把 `dispatching` 发布与步骤统一置为 `outcome_unknown`（`PROCESS_RESTARTED`），绝不自动重试。
- `WorkbenchDraftTransport.find()` 只读逐步重建证据（分支 SHA、commit blobs、Draft PR），完全匹配才返回 PR 编号并补写回执。

### 5. 失效与导出语义

- 同 finding 下不同 `payload_hash` 的 `ready/exported/failed` 行在入队时被置 `stale`（`PAYLOAD_CHANGED`）；若旧行仍在 `dispatching/outcome_unknown`，新入队被拒绝（`PUBLICATION_IN_FLIGHT`），避免两条发布同时写远端。
- 任务取消时 `ready/exported → cancelled`；`dispatching` 不取消而是 `outcome_unknown`，保留对账义务。
- 无写授权时状态为 `exported`，finding 仍为 `waiting_approval`，`next_action=approve`，接口返回完整 diff/bundle；不声称已发布。

### 6. API 与状态

- 新增 `POST /api/v3/workbench/tasks/{task_id}/findings/{finding_id}/publish` 与 `POST .../reconcile`；`approve` 语义不变。
- `PublicationRecord.status` 扩展 `dispatching/outcome_unknown/base_changed/write_permission_required/failed/cancelled`；`derive_stage` 仅把 `published` 映射到 `pr_created`，其余保持 `waiting_approval`。
- 每次发布状态变化写 `kind="pr.receipt"` 事件，幂等键包含 approval、payload hash 与行状态。

## 验证

  - fixture 审批经 outbox + dispatcher 产生 branch/commit/pull_request 三步骤回执与 `published`；
  - live 无写授权 → `exported`、attempts=0、完整 patch、`waiting_approval`；

  - payload 变更使旧发布 `stale`，只有新 payload 到达远端；
