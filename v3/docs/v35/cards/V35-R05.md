## 目标

用户只需选择自然语言目标与“只调查 / 允许尝试修复”，Web、CLI 调同一 API；页面能解释每个成功声明的证据。

## 实现

### 1. 任务视图补齐可解释字段

`WorkbenchService.view()` 在既有 commit、coverage、findings、timeline、next_action 之外新增：

- `usage`：`runs`（audit/repair/verifier 计数，来源 `app.workbench_run_links`）、`retries`（`app.runs.attempt_no` 与 publication `attempts` 推导）、`cost`（`app.usage_calls.settled_micros` 汇总，含 `calls/unknown_calls`，fixture 全为 0 费用但保留调用数）。
- `pending`：派生状态，只取 `waiting_for_dependencies`、`waiting_approval` 或 `null`，附 `reason_code/reason`。
- `failure`：最近一次 `failed` 事件的结构化原因（`stage/kind/reason_code/reason/at`）。
- `finding.pull_request_link`：只有 `remote == "github"` 且 URL 以 `https://github.com/` 开头才非空；fixture 回执永远为 `null`，同时写回 `publication.pull_request_link`。

### 2. 依赖缺失不再等同于执行失败

- 新增 `_DEPENDENCY_CODES`：`REPO_ANALYSIS_PROFILE_REQUIRED`、`REPO_ANALYSIS_PROFILE_INVALID`、`REPO_ANALYSIS_SCOPE_DENIED`、`GITHUB_READ_CREDENTIAL_REQUIRED`、`WORKBENCH_LIVE_REPAIR_SANDBOX_REQUIRED`。
- `_start_audit()` 捕获上述错误时把任务从 `investigating` 迁到 `waiting_input`（`status=ready`），写 `kind=dependencies.waiting` 事件并保留错误码；不再落 `failed`。`next_action=wait_for_dependencies`。
- 无 GitHub 写授权时 R04 的 `exported` 语义保持不变，视图 `pending.state=waiting_approval`、`reason_code=WRITE_PERMISSION_REQUIRED`，不显示失败。
- `handoff.waiting` 同样派生为 `waiting_for_dependencies`；`cancelled/completed` 不显示 pending。

### 3. Web 端完整 Diff 审查与审批绑定

- 新增“加载完整 Diff”按钮，调用既有 `GET .../findings/{id}/diff`，页面展示完整 unified diff 与 `payload_hash`、`diff_sha256`、前后测试回执。
- 审批按钮在 `reviewedDiff.payload_hash === finding.approval.payload_hash` 之前保持禁用；点击后再次校验并弹出包含 `payload_hash` 的确认框，只提交已审查的 hash。切换 finding 会清空已审查状态。
- 创建表单生成并复用一个 `client_request_id`（`crypto.randomUUID`），提交期间禁用按钮，成功后清除；刷新/重复提交不会创建第二个任务。
- 详情页展示固定 commit、扫描范围、`observed_coverage`（已读/未读文件）、`usage`、`failure`、`pending`；fixture 发布只显示“fixture 回执（非 GitHub 链接）”，不生成锚点。
- 页面不渲染任何 token；token 只保存在 `sessionStorage` 并放入请求头。

### 4. CLI 与 API 对齐

- `mgar workbench --action publish|reconcile` 接入与 Web 相同的 finding 级端点；`status/list` 输出同一任务视图，因此 `stage_label`、`pending`、`usage`、`failure` 在 CLI/Web 完全一致。
- `pause/resume/cancel/messages`、`diff`、`approve` 原本已共用同一 API，本卡不新增第二套语义。
