## 目标

用户只需选择自然语言目标与“只调查 / 允许尝试修复”，Web、CLI 调同一 API；页面能解释每个成功声明的证据。

## 执行要点

1. 显示固定 Commit、扫描范围、实际已读/未读文件、风险排序 Finding、Evidence、测试回执、Diff、费用、Run/Retry 数与下一步动作。
2. 明确区分 `Suspected`、`Reproduced`、`Patch Verified`、`Waiting Approval`、`PR Created`；不得把建议补丁显示为修复成功。
3. 支持 `pause/resume/cancel/follow_up`、历史任务、失败原因。
4. 页面提供完整 Diff 审查，由用户对 `payload_hash` 授权；不展示或写入真实 Token。
5. 不支持的真实依赖或 GitHub 授权显示 `waiting_for_dependencies / waiting_approval`，而非“执行失败”。
