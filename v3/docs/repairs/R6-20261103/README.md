## 问题、修复过程与证据

[问题登记及处置](issue-register.json) 逐项记录表现、原因、修改、工程与真实验收；[残余错误复现](v6-residual-reproductions.json) 保留模型额外字段和两份遗漏 paid 过滤补丁的原文与真实隐藏测试回执；[JSON 请求错误及账单核对全过程](json-mode-incident.md)。

1. 数值错误：原 cross-07 C 报 48.00，[真实 SQL 复现](numeric-reproduction.json) 为 20.00。改为实际读取行、SQL count/sum/min 与精确 Decimal 交叉检查，正确处理零/负数及先取消后支付；运行时不读取隐藏答案或 Case.rows。
2. 输出/权限：显式公开字段契约、状态前置判定、实际 ACL 撤销/具名文档/来源版本检查，数值/引用末端失败关闭；不根据负例标签决定答案。
3. 审计回执造成假冲突：带时间戳的观察回执只进私有 CAS；稳定行、查询和指标进入所有模型消息，重复内容去重。
4. 专家结构错误和引用：仅丢弃已知模式错误的专家摘要并记录原因，主 Agent 使用原始证据；未知费用/网络错误仍停止。模型选实际来源的 quote_id，精确还原原文，不模糊修补。
5. 代码修复：模型返回受限函数体，可信冻结函数框架机械生成 diff；仍经原 AST 权限检查、实际公开及 28 个隐藏 Go 子测试，无参考补丁泄露。不据受控样例断言模型修复可靠。
6. v5 HTTP 400：主提示漏写 JSON，第一项三次后停止。先保留未知预占，再用用户完整 11 月 5 日账单核清；原拒绝保持 FAIL/89 NOT_RUN，不重发。补主提示、调用前和预检校验及严格单拒绝核账；详见专档。
