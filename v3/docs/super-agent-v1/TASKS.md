# Super-Agent V1 完整任务书

全部状态：**PLANNED**。短号 SA00–SA24 对应完整 ID `SAV1-00`–`SAV1-24`。
`HV4-Hxx` 是 [Harness V4 任务](../harness-v4/TASKS.md)，属于外部前置，不是已完成项。
每卡以一个可复现交付单元执行；大卡可以按接口、实现、集成拆子提交，验收完整后才 DONE。

## 执行与交付规则

1. 每卡交付代码/迁移、契约或配置、相关回归、操作说明和分门验收摘要；仅规划卡
   可交付审计/ADR。实现时注册真正的 `make verify TASK=SAV1-xx` 目标，不预注册空测试。
2. 使用原 Engine 事务边界及显式前向迁移，外部调用在事务外；不新建平行业务数据库。
3. 模型、通知和发布的授权分别记录。Shadow 不改代码、不发送消息；发送测试也需
   具体的试验渠道和通知许可。安装应用、订阅群和开通平台权限不属于本轮文档交付。
4. 已知回执可复用；未知模型/消息/外部写结果保留预占或待核对状态，不盲重试。
5. 原始日志放 `evidence/super-agent-v1/<card>/<attempt>/`，公开摘要后续放 `accept/`；
   不提交聊天原文、平台密钥或访问令牌。失败记录与未实测范围原样保留。
6. 成功、权限与路由状态由系统契约及独立判定产生；LLM 建议、Memory 和平台正文
   不能改写已冻结验收要求或提升授权。

## SAV1-00：冻结范围、复用审计与架构 ADR

- **工作**：对照当前 Trigger/Thread/Router/Subscription/Proactivity/Watchdog/Outbox
  调用链，冻结单群单仓首版、角色、事件类型、数据外发和试用范围；定义 Harness
  能力门与 Source/控制层可并行开发的边界。为团队规则自主性、来源身份、通知
  预授权建立正式 ADR，明确对旧 R3/受限投机规则的版本化扩展。
- **验收**：每个“复用”项有代码/测试证据；Harness 前置均可定位，未实施不记为
  可用；原历史 FAIL/NOT_RUN 保留。冻结路由标注协议、试用指标、预算方案和失败分母。
- **产物**：baseline、范围清单、ADR、状态所有权、需求映射及试验计划。
- **主要位置**：`domain.py`、`coordination/engine.py`、`routing/`、`proactivity/`、现有 ADR。

<a id="sa01"></a>

## SAV1-01：Source/事件/身份与领域契约

- **工作**：定义 SourceRegistry/Adapter/Channel、SourceEvent v1、SourceThreadRef、
  ActorRef、能力与健康契约；映射到现有 Trigger/Thread/Ticket/Run。未确定仓库的
  输入放受控来源收件箱，不用伪 Issue；为安装/租户、版本和关联添加前向迁移。
- **验收**：同名群、两个安装下同 ID、大小写敏感用户 ID、无原生话题和晚到事件
  均可表示；旧 GitHub/CLI/Web 契约不变。Source 缺历史/发送查询能力能明确声明。
- **产物**：schema、迁移、兼容适配、事件与来源能力样本；不注册新的业务主状态机。

<a id="sa02"></a>

## SAV1-02：平台身份绑定与控制角色

- **工作**：建立安装/租户内的可信来源身份，与控制台管理员、请求者、任务控制者
  和上下文提供者关联。平台签名/安装证明提供身份，跨平台绑定由管理员核对或可验证
  流程产生；正文、显示名和模型不能绑定身份。
- **验收**：伪造 sender、同名用户、冒充机器人、引用别人的请求和跨租户 ID 不生效。
  能贡献日志的人不能随意撤销/扩权/审批；已撤销身份即时阻止新的特权操作。
- **产物**：身份映射、角色检查、审计和管理 API；首版不要求开放多租户注册。

<a id="sa03"></a>

## SAV1-03：四层策略、版本与撤权

- **工作**：实现 Receive/Admission/Execution/Notification 的独立策略及 disabled/
  shadow/auto_investigate/auto_repair。包含 Source、群/用户、仓库/路径、能力、
  有效期、规则依据、安静时间、总预算、通知目的地和内容边界；策略有版本和签署人。
- **验收**：同样正文在不同接收者/模式下得到正确结果；接收不隐含执行或回复授权。
  旧只读/显式请求许可不自动升级。撤权使待执行工具、租约和待发消息失效，在途
  操作保留真实结算/对账。保存策略有并发版本检查，可预览影响。
- **产物**：策略契约、验证器、签署/撤权记录、迁移和模式测试矩阵。

<a id="sa04"></a>

## SAV1-04：持久入站、幂等、编辑与缺口

- **工作**：Source Gateway 经受信入口向 Engine 提交事件，提交后 ACK；实现复合
  去重、正文冲突、消息编辑/撤回、新旧版本、乱序、来源游标、时效和有界积压。
  校验回调 ACK 行为，必要传输缓冲需加密、限额且仅重交 Engine。
- **验收**：重复/并发投递只产生一次业务输入；崩溃、PG 暂停和 SDK 自动 ACK 的
  实际边界可复现。补拉重新检查权限，历史消息不自动开工；无法回放时记录 gap。
  不在接收范围的正文不落入模型输入、Recall、普通日志或长期存储。
- **产物**：接收凭证、游标/缺口、保留策略、重放工具及真实 PG 测试。

<a id="sa05"></a>

## SAV1-05：GitHub App 与事件源适配

- **工作**：复用原验签/去重分支，增加安装身份、短期凭据 Broker、Issue/PR/
  review/comment、CI/workflow/check 规范化；保留仓库、PR、head SHA 和 run attempt。
  配置仓库/事件/机器人范围，按实际 API 能力做有界补拉。
- **验收**：假签名、非授权安装、fork/PR head 变化、重复 CI 和自身结果不创建错误

  旧 Issue Webhook 回归通过；不把 PR 评论再当不支持事件静默丢弃。
  旧/新入站灰度切换只有一个业务所有者，不能同一投递触发两套任务。
- **产物**：GitHub Adapter、安装设置/健康、权限清单、录制样本与限流/重放记录。

<a id="sa06"></a>

## SAV1-06：飞书机器人来源适配

- **工作**：使用官方 SDK 与机器人身份接入 `im.message.receive_v1`；首选经过验证的
  长连接，Webhook 作为可选方式。配置安装/租户、群、发送者、@、回复话题和事件范围，
  明确实际 scopes、ACK/重连和历史读取能力，所有凭据由服务端安全配置管理。
- **验收**：授权群消息/指定用户/@/既有话题跟进正确规范化；未授权群和私人会话不
  被读取/保留。机器人自身输出不会再次开任务。断线重连、权限不足、令牌失效和
  丢失区间有准确状态，不假定长连接提供无限历史重放。
- **产物**：Feishu Adapter、权限/能力实测表、来源设置引导、受控录制与实际渠道记录。

<a id="sa07"></a>

## SAV1-07：项目总预算、配额与费用归集

- **工作**：将 Router、Worker、验证、Recall 和子任务调用汇入同一项目/组织总额，
  Run 只领取子额度；设置小时/日预算、Token、候选/队列/槽位、来源速率和通知配额。
  窗口时区、成本价格版本与规则签署记录一起冻结。
- **验收**：多事件同时创建任务不能绕过项目总额；切换模式/新建 Run/跨日不退款
  unknown 预占。无事件不发周期模型请求。缺预算时仅做允许的确定性过滤，明确标注
  Router 语义评估未运行。用户无需配置模型调用轮数。
- **产物**：共享预算/预占、配额、用量视图、并发与跨窗口测试。

<a id="sa08"></a>

## SAV1-08：Fast Path 与无副作用影子观察

- **工作**：实现安装/群/用户/时效/机器人/重复/自身结果/冷却规则；已验证控制指令
  走高优先级路径；按话题合并合格消息。Shadow 记录候选、拒绝理由及假设动作，
  SA09 接入后做获准的语义评估；此时不创建真实 Worker、发送回复或修改仓库。
- **验收**：未获准事件不进模型；高频无关消息不会制造模型空转。Shadow 下显式 @
  请求也不执行，模拟结果不伪装为测试/通知回执；切到自动模式必须由管理员保存。
  反馈循环、自身 PR/机器人结果和历史回放有去重/冷却记录。
- **产物**：策略决策日志、影子预览、基准过滤集、触发和成本分布。

<a id="sa09"></a>

## SAV1-09：Router/Eval 严格候选与校验

- **工作**：复用 Routing/RouterWorker，支持环境信号的 ignore/observe/attach/create/
  ask 提案。将可靠身份、策略、相关资源和有界候选提供给模型，程序构造版本化决定。
  缺仓库/上下文时保留候选或澄清；模型没有 Shell、群发和业务写工具。
- **验收**：Schema、scope、revision、epoch、规则版本、actor 或预算不符时拒绝提交。
  模型失败不自动产生任务；unknown 不重发。显式任务、模糊闲聊、引用和机器人信号
  在标注集上分别报告精确率/召回率，工程测试与语义成绩分开。
- **产物**：新提案/策略校验、冻结提示版本、候选录制和逐例评估。

<a id="sa10"></a>

## SAV1-10：跨来源话题/任务关联与查重

- **工作**：维护平台话题、issue/PR/CI、代码版本及 Ticket 的可追溯关系；以安装内
  明确资源引用优先，模型只建议关联。同群多问题分别处理；同问题跨来源避免重复建单。
  纠正/合并用关系和新 revision 表示，保留原事件与旧决定。
- **验收**：同名话题、模糊标题、不同仓库同 Issue 编号和跨私密群不能误合并。
  关系不确定时不随机选择；并发建立同一任务有事务性去重。PR force-push/CI 的 SHA
  不同不会继承旧树验证；纠正不把已执行工作后台换到另一个授权目标。
- **产物**：ThreadLink/TaskCorrelation、候选说明、纠正 API 和混淆负例。

<a id="sa11"></a>

## SAV1-11：动态订阅、Mailbox 与交回

- **工作**：扩展 primary/context_only/observer、TTL、消费游标、unsubscribe/handback
  和关闭后跟进。订阅消息省略新任务 LLM 评估，仍检查接收、读取、控制角色和 Mandate。
  避免整群变成一个 Thread；积压分段可读取，不无限扩展模型上下文。
- **验收**：同话题新日志只送已有任务；只读机器人/旁观者内容不能改权限或目标。
  交回/退订与并发投递的快照一致；旧 Worker/已撤权订阅不再消费。晚到消息、结束后
  状态查询和新 Run 重开可区分，机器人不擅自复活已停止任务；交回循环会被停止。
- **产物**：订阅迁移、投递/消费凭证、交回 API 和真实并发恢复测试。

<a id="sa12"></a>

## SAV1-12：Scheduler、Assignment 与租约

- **工作**：在 Engine 事务中领取队列，分配 Run/Session/工作区及单个有效 lease/epoch，
  由独立 Worker 回报。按项目/来源/任务年龄公平调度，限制 CPU/内存、活跃数和准备
  阶段；Redis 丢失后从 PG 重建。实际执行接口复用 Harness Broker。
- **验收**：多个调度进程竞争不重复领写任务；失联/过期 Worker 不再执行或提交
  成功；两个任务各有独立可写目录。后台 Job 未结束时不错误释放槽位，等待用户
  能安全释放资源并保留状态。CI 洪水不饿死已获准的人类任务。
- **产物**：Assignment/Lease、队列与资源视图、容量/公平性和故障测试。

<a id="sa13"></a>

## SAV1-13：Coding Worker 与 Mandate 接线

- **工作**：将 Source/策略生成的 Mandate 转为 Harness Coding Run，绑定仓库版本、
  路径、预算、上下文和精确任务目标；实际读/改/测试经过原 Broker/Verifier。GitHub
  App 私有仓库令牌经受信快照通道使用，不交给项目进程；旧公开只读 API 不被放宽。
- **验收**：只能在 HV4-H11/H12 能力与恢复门通过的范围开放真实修复。用户群发言
  可在受控模式引发真实工作区多轮修复；恶意仓库数据不能扩权。已验证产物绑定同一
  代码树和任务目标；只有报告、假文件或 fixture Provider 不能给真实编码门 PASS。
- **产物**：WorkerBridge、授权映射、私有/公开仓库支持矩阵、真实 Harness 接线记录。

<a id="sa14"></a>

## SAV1-14：异步 Job、持续输入与安全点

- **工作**：把新消息、控制限制、测试完成、来源编辑/删除和策略变化写入持久 inbox；
  耗时命令用可查询/取消 Job 运行，Worker 在安全点应用有效指示。输入带 revision，
  不将只读日志中的命令当用户指示。
- **验收**：运行测试时收到“不要改数据库”，后续未授权编辑被阻止；已开始的原子
  编辑/外部写正确收尾，费用仍结算。重复消息只消费一次，旧回复不能执行新目标
  下的操作；控制台显示 received/applied/blocked。重启后 Job/输入不丢、不重复执行。
- **产物**：统一异步事件、Job 唤醒/中断、安全点协议及在途约束变化测试。

<a id="sa15"></a>

## SAV1-15：可鉴权 Chain of Recall

- **工作**：提供按 ID/关系从来源事件、Thread、Ticket、Run/Job 到 Evidence/Artifact、
  审查和 Delivery 的有界检索工具；复用 Memory/Context/CAS，不把历史聊天全文重新
  送模型。内容与权限版本、过期/删除、来源 gap 和不确定性可见。
- **验收**：“昨天的登录问题怎样了”能查到正确授权任务及真实状态；同名/跨群/
  跨仓/已撤权数据不泄露。逐跳鉴权、循环/深度限制、原文分页和删除失效通过；摘要
  不能自行生成新事实或授权，未能定位时提出有用澄清。
- **产物**：Recall API/工具、关系索引、时效和 ACL 测试及检索质量记录。

<a id="sa16"></a>

## SAV1-16：静默自主任务生命周期

- **工作**：在已冻结团队规则下开放自动调查/隔离修复，将 shadow would_accept
  升级为带有效 Mandate 的任务；管理冷却、重复线索、主动任务 TTL、停止、等待和
  新 Run 重验。配置变更/规则关闭向活跃任务传播，但不重置旧账本。
  明确获准的定时信号使用持久时区/触发游标，漏过的 tick 有界合并；默认不开启
  周期付费任务，重复 tick/DST 不重复创建任务。
- **验收**：无关讨论没有 Worker/回复；合格信号按规则开工并记录依据。没有新进展
  不无限占资源；用户停用后不再自动创建任务。结果、失败、预算耗尽和待审批在
  控制台可查，静默不掩盖未完成；机器人及自身结果不形成无限任务链。
- **产物**：主动生命周期、模式切换审计、规则命中解释和回退演练。

<a id="sa17"></a>

## SAV1-17：多渠道 Outbox 与节制通知

- **工作**：扩展 Channel/Dispatcher，在具体通知授权下将结果/必要提问/审查/重要
  故障发回原话题；内容 hash 与模板、接收者、当前 ACL、频率/安静时间一起校验。
  同步记录来源因果链，支持聚合、冷却、平台幂等键和按能力查询发送结果。
- **验收**：普通工具进度不群发；同一结果不会因重连或重启重复入 Outbox。远端
  接收后丢回执保留 unknown，能查则只读对账，不能查则等待人工，不盲重发。
  私密日志不进入公开 GitHub；过期/撤权待发消息取消，自身消息不会再次触发工作。
- **产物**：消息 Action/策略审批、Delivery 回执、通知计划和真实/受控通道测试。

<a id="sa18"></a>

## SAV1-18：Review、精确审批与 Draft PR

- **工作**：将 Worker 的真实 Diff/tree/测试结果封为 Review Bundle，在已认证控制台
  审查和批准；通知只说明可审查产物。按现有 Action/Outbox 发布 Draft PR，并绑定
  PR/CI 到原 Ticket；必要写凭据与读凭据分开。
- **验收**：陈旧树、改变目标、补丁未验证、审批过期和错误 actor 无法发布。
  普通 IM 文本不能替代具体 hash 审批。PR 接收后丢回执只读恢复，不重复创建。
  未授权 live 写时停留待审批，fixture:// 不显示为真实 PR；不默认 merge/部署。
- **产物**：跨来源审查入口、精确审批/发布回执、原话题关联和真实测试仓库证据。

<a id="sa19"></a>

## SAV1-19：来源、策略、Shadow 与任务控制台

- **工作**：在现有账户首页增加来源/群/用户、实际权限健康、规则预览、Shadow 决定、
  任务关系、Worker/Job、费用、通知及待审动作。支持全局停用、按来源撤权、按任务
  停止；填写凭据仍用安全网页输入，缺配置给具体引导。
- **验收**：无需手改多个配置文件就能完成首版范围设置；连接在线和消息权限不足
  分开显示。能说明为什么忽略/关联/开工，以及“未运行语义评估”。未通过 Worker
  能力门时不开放自动修复开关；浏览器关闭不取消任务。观察页可在 S1 先行交付。
- **产物**：控制台、浏览器测试、权限与工作状态说明、管理员操作流程。

<a id="sa20"></a>

## SAV1-20：常驻部署、Watchdog 与运维

- **工作**：在在线服务器分离 Source 接入、API/Engine、调度、Worker、Dispatcher 与
  独立 Watchdog；明确部署网络/凭据边界。使用受支持的 HTTPS/来源回调/Origin 配置，
  PG/Redis 保持内网。加入来源断线、gap、积压、语义进展、Job 和租约指标。
- **验收**：关闭用户浏览器/电脑后云端任务继续，断开本地唯一 Runner 时明确等待。
  守护进程不依赖桌面登录；服务重启/队列恢复、来源失联与通知失败有准确告警。
  Watchdog 不重置预算/扩权，心跳不冒充任务有进展；备份恢复覆盖 DB/CAS/密钥。
- **产物**：Compose/服务管理、TLS/Secret 配置、健康/指标、故障与备份手册和演练。

<a id="sa21"></a>

## SAV1-21：隐私、安全与灾难恢复验收

- **工作**：验证从接收、模型输入审计、Memory/CAS 到导出/通知的完整数据生命周期；
  注入源消息、撤权、跨群/项目、配额、假身份、双调度、旧 Worker、流/回执丢失、
  真实隔离 PG 重启及存储恢复故障。关键约束从早期卡开始执行，本卡汇总证据。
- **验收**：越权操作、未授权数据入模型、跨范围泄露、未知副作用盲重试与假完成
  均为 0；删除/撤权使检索和待发内容失效，保留最小审计。未演练的故障/平台标
  NOT_RUN；不通过重启生产数据库来替代隔离测试。
- **产物**：威胁与故障矩阵、逐例日志/回执、数据保留/清理策略和恢复报告。

<a id="sa22"></a>

## SAV1-22：多渠道真实闭环与长期试用评测

- **工作**：执行冻结的过滤/路由、订阅归属、真实编码和通知任务；分开工程重放、
  真实平台、真实模型、实际发布与长期运行门。进行至少 72 小时连续运行和受控
  故障演练，再进行有操作者反馈的团队试用。
- **验收**：按 [验收协议](ACCEPTANCE.md) 的预冻结门槛报告；包含真实飞书输入到
  真实修改/测试/原会话反馈、GitHub CI 跟进、恢复、撤权和 quiet 模式。噪声、延迟、
  费用、失败分母与人工介入均有数据，不用 fixture 通过替代真实修复成绩。
- **产物**：冻结集、逐例与长期运行报告、失败分类、试用反馈和升级/回退决定。

<a id="sa23"></a>

## SAV1-23：可复现安装、发布与上线交接

- **工作**：交付版本锁定、安装/迁移、来源配置、权限检查、从 Shadow 开始的引导、
  升级/回退、费用上限、故障排查和数据清理。复用 Harness H18 的已有产物；没有

- **验收**：干净服务器与既有安装分别演练，源/模型/执行/通知/发布的实际能力和

- **产物**：版本包、支持矩阵、上线核对/回退与管理员交接记录。
