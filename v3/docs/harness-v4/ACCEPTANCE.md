# Harness V4 验收与评测方案

状态：PLANNED。以下是建议门槛，H00 必须在实施和实验前冻结版本、任务与阈值；
本文件不代表任何未来门已通过。当前能力及历史失败见 [总览](README.md)。

## 1. 必须分开的门

| 门 | PASS 所需证据 | 不足以证明什么 |
| --- | --- | --- |
| engineering_gate | 真实 PG/CAS/沙箱集成、相关回归、静态检查、确定性故障测试 | 受控模型不证明实际模型能完成任务 |
| security_gate | 隔离/越权/凭据/恢复/预算等关键场景全部通过 | 不宣称能抵御所有未来攻击或已具备多租户能力 |
| live_model_gate | 明确许可下的真实供应商调用、完整用量和错误映射 | 模型能回复不证明能修改并验证项目 |
| live_agent_gate | 模型自主调用真实工具，完成任务并通过独立行为/回归判定 | 小样本不证明与其他产品全面持平 |
| live_publication_gate | 独立写许可、完整已审 Diff、原 Action/Outbox 及远端回执核对 | fixture PR 或本地 Git commit 不算真实发布 |

M2 编码 MVP 要求前四门在所声明范围内通过。外部发布可以为 NOT_RUN，产品明确
显示其边界。某门实际执行失败必须保留 FAIL；以后修复产生新结果，不覆盖旧记录。

## 2. 单个任务的完成凭证

每个最终完成结果至少关联：

- task/thread/run、用户目标与 acceptance_revision、工作区和基线 Commit/manifest。
- 当前能力许可与模型配置摘要；步骤/调用/命令 ID、epoch、预算预占和真实用量。
- 修改前后 tree hash、真实 Diff、所有变更文件与补丁产物 hash。
- 执行命令、cwd、环境/依赖摘要、退出码、测试数/跳过数、日志 hash、目标代码树。
- 已满足/未满足的验收项、失败尝试和仍需人工判断的事项。

引用核验与模型评审适用于解释性结论；代码任务的通过还须满足对应行为判定。
“模型说完成”“文件发生变化”“命令退出 0”“最终测试全绿”各自都不是单独充分条件。
修改后没有执行必需验证时，结果明确标为未验证/未完成。

## 3. 工程功能矩阵

| 场景 | 通过条件 | 关联卡 |
| --- | --- | --- |
| 原有只读问题/追问 | 仍能固定版本、引用源码、按当前有效许可新开追问 | H01、H08 |
| 本机脏工作区 | 原改动和 untracked 文件保留，最终应用有 hash 冲突检查 | H03 |
| 大文件小修改 | 至少 142KB 文件的局部改动无需完整文件输出，真实 Diff 正确 | H05 |
| 多文件原子变更 | 全部成功或全部回滚，重复操作不重复插入 | H05 |
| 先失败后修复 | 有真实失败回执，模型依据错误再改动并通过 | H06、H07 |
| 绿色基线新功能 | 新需求行为验证通过，原有回归保持通过 | H07 |
| 绿色基线重构 | 指定行为等价和回归通过，不要求先制造一个失败测试 | H07 |
| 旧三次修复限制 | 新策略在有进展、资源足够时可超过旧限制，旧许可上限仍有效 | H07 |
| 不可准备的依赖 | 实际返回缺少的包/源/系统能力，任务等待输入，不伪造测试通过 | H06 |
| 应用启动 | 指定环境中真实就绪，拥有可查询的进程/端口，能停止或按租约清理 | H06 |
| 无测试/全部跳过 | 不当作满足要求的行为验收通过 | H06、H07 |
| 测试或条件被篡改 | 独立判定器仍发现原需求未满足，不授予已完成状态 | H07、H12 |
| 连续空搜索/补丁往返 | 后台识别无进展，保留结果，预算内不无限循环 | H07 |
| 中途补充指示 | 持久收到一次并在安全点应用，旧回复不能覆盖新目标 | H09 |
| 缺信息/缺能力 | 有具体问题或动作弹窗，用户输入和工作进度保留 | H04、H09 |
| 实时日志和 Diff | 真实工具事件先于最终结果出现；慢客户端不会阻塞执行 | H06、H09 |
| 刷新/断线重连 | 按游标恢复，不串会话、不重复执行工具 | H09 |
| 长上下文 | 多次压缩后仍保留目标、权限、失败、版本与可读取的原文 | H10 |
| 多项目并发 | 工作树、命令、事件与资源额度相互隔离 | H03、H11 |
| Web/CLI/SDK | 对同一任务状态、Diff、用量与回执一致 | H13 |

运行中断和供应商未知用量需覆盖真实传输边界，不仅 mock 最终状态。编辑/测试
使用真实文件和进程，集成验收使用 PostgreSQL，不使用 SQLite 替代。

## 4. 安全与恢复矩阵

以下关键场景要求全部通过，目标值：越权操作 0、未知副作用盲重试 0、跨任务覆盖 0、
被测试系统误报完成 0。测试集合在 H00 冻结并由各卡扩充，不能通过删除失败场景放行。

| 类别 | 必测故障/负例 |
| --- | --- |
| 文件系统 | 路径穿越、symlink 逃逸、变更时路径替换、保护路径、并发 pre-image 变化 |
| 进程与网络 | 子进程越界、命令超时、后台子进程泄漏、未授权网络、项目代码读取宿主密钥 |
| 指令与扩展 | README/Issue/日志/Memory 注入、AGENTS/Skills 扩权、同名插件工具、MCP 未授权副作用 |
| 身份与范围 | 会话过期/CSRF 更新、仓库撤权、工作区撤权、旧许可恢复、新追问预算、过期 epoch |
| 预算 | 并发预占、输入/输出用量、已知拒绝有界重试、缺 usage 保留预占、未知调用不重发 |
| 补丁崩溃 | 应用前、应用后回执前、CAS 保存后、多个文件中间中断；重复请求和旧 Worker 回写 |
| 命令崩溃 | 领取后启动前、启动后句柄保存前、执行后回执前；恢复查询/终止，不擅自重跑有副作用命令 |
| 模型崩溃 | 请求发送前、流中断、供应商返回后结算前、结算后 checkpoint 前 |
| 服务与数据库 | 控制进程 SIGKILL、Runner 失联、独立测试 PG 实际重启、DB/CAS 恢复和 hash 核对 |
| 审批与发布 | Diff/tree/目标变化使旧审批失效、回执丢失后的只读对账、fixture 不显示真实 PR |

H15/H16 增加设备伪造、重复领取、配对撤销、跨用户/项目 IDOR、事件及 CAS 泄露、
双控制器和租户配额测试。MVP 的单管理员验收不能直接给这些新增范围标 PASS。

## 5. 首批任务集与门槛

建议 H00 冻结 **12 个开发任务 + 12 个独立持出任务**。至少覆盖 4 个真实项目，
Python 与 JS/TS 均有覆盖；保留现有 Go 任务作为兼容回归。每份集合按以下类型组成：

| 类型 | 每集合数量 | 例子 |
| --- | --- | --- |
| Bug 修复 | 4 | 边界条件、跨文件错误、现有测试失败、需要新增复现用例 |
| 新增功能 | 3 | 绿色基线下增加 API/CLI 行为并补测试 |
| 重构 | 2 | 保持公共行为，修改多个实现文件 |
| 环境/启动 | 2 | 处理可支持的依赖与构建、启动应用并验证就绪 |
| 大文件/多轮 | 1 | 大文件局部修复，首个方案失败后利用反馈继续 |

这些为任务组成建议，不是已存在的真实成绩。H00 明确项目/Commit、依赖、测试和
资源限额，并在模型见到任务前冻结；dev/holdout 使用不同任务，避免只换名字/变量。
持出判定器、测试答案和评分器控制代码不能进入模型上下文。模型自行新增的测试
可提高工程质量，但不作为唯一独立评分依据。

建议 MVP 放行阈值：

- dev 至少 10/12 完成；holdout 至少 9/12 完成，按总任务数作为分母。
- 工程功能矩阵及关键安全/恢复场景全部通过；已要求的回归不得出现新增失败。
- 未满足行为要求却标完成为 0；越权与未知操作盲重试为 0。
- 每次运行的 Token、费用、时间在冻结资源内；未知用量不准按 0 费用计为完成。
- 至少有真实模型完成跨文件修改、失败反馈后修复和绿色基线新增功能的记录。

这里的数值是建议发布门槛，需在 H00 一次性冻结。小规模持出集用于当前版本放行，
不构成行业能力排名；如未达标，记录 FAIL、定位原因并新建候选版本。持出任务被
用于调参后，下一轮推广需要新的独立持出集，不能反复重试后只报告最好成绩。

## 6. 测量与对照方法

每例记录：完成/未完成原因、任务类型、代码树与判定器 hash、模型/运行时版本、
公开/独立测试、所有失败尝试、输入/输出 Token、已结算/预占费用、墙钟、工具/命令
耗时、无进展占比、压缩次数/丢失项、人工干预和恢复结果。

- 同 Harness 比模型：固定任务、工具、预算、环境与评分器，变更模型配置。
- 同模型比 Harness：仅当双方支持同一模型和资源约束时，固定模型/任务/环境，比较
  MAGR 与官方 DSH 等运行时；记录系统提示与工具配置差别。
- Codex/Claude Code 如果无法使用同一模型，结果只能称整产品对比；无访问权或
  未获相应实验许可时记为 NOT_RUN，不根据演示推测数值。
- 单次独立运行的成绩与重新开 Run 的重试成绩分别统计；循环内反馈均计入当次预算。
  隐藏的人工修复或重启成本不能剔除。
- 小样本报告逐例、总数和不确定性。时延统计样本不足 20 时优先报告中位数/最大值，
  不用不稳定的 P95 制造精确印象。

交互目标：本机任务创建/中断请求的持久接收和首个状态事件，在健康测试环境中
不超过 2 秒；不把它等同于供应商首 Token 延迟。长任务用加速受控测试验证大量
步骤/压缩，再用经过许可的真实任务验证能力；不能只让模型空转一小时宣称长任务通过。

## 7. 每卡验收摘要模板

实施时创建真实摘要，结构至少包括：

```json
{
  "card": "HV4-Hxx",
  "source_commit": "<commit>",
  "source_sha256": "<fingerprint>",
  "scope": ["<已验收的平台、语言、工具和场景>"],
  "engineering_gate": "PASS|FAIL|NOT_RUN",
  "security_gate": "PASS|FAIL|NOT_RUN",
  "live_model_gate": "PASS|FAIL|NOT_RUN",
  "live_agent_gate": "PASS|FAIL|NOT_RUN",
  "live_publication_gate": "PASS|FAIL|NOT_RUN",
  "commands": [],
  "task_results": [],
  "known_failures": [],
  "evidence_paths": [],
  "usage": {"known_cost_micros": 0, "reserved_cost_micros": 0},
  "limitations": []
}
```

这是未来摘要的结构示例，不是当前验收结果。每个 PASS 都必须能定位到真实命令、
判定器及不可变回执；保留所有失败尝试。规划文档的链接/DAG 检查仅验证任务书本身，
不能把工程门、真实 Agent 门或发布门改为 PASS。
